# Analisis Komparatif Platform Web, Desktop, dan Mobile

## 1. Tabel Analisis Platform

| Aspek | Web | Desktop | Mobile |
|---|---|---|---|
| Bahasa utama | HTML, CSS, dan JavaScript/TypeScript. Backend dapat menggunakan JavaScript, Python, Java, PHP, dan bahasa lain. | Bergantung pada teknologi: C#/.NET, Java, C++, Python, Swift, dan lainnya. | Android umumnya menggunakan Kotlin atau Java; iOS umumnya menggunakan Swift. Teknologi lintas platform seperti Flutter/Dart dan React Native/JavaScript juga digunakan. |
| Arsitektur | Umumnya menggunakan arsitektur client-server. Browser menjadi client yang mengakses aplikasi atau layanan melalui jaringan; sebagian aplikasi juga dapat menjalankan fungsi di sisi client. | Aplikasi dipasang dan dijalankan pada sistem operasi komputer. Dapat memproses data secara lokal dan/atau terhubung ke server. | Aplikasi berjalan pada perangkat bergerak dan memanfaatkan fitur perangkat seperti kamera, GPS, sensor, serta penyimpanan. Dapat berarsitektur lokal, client-server, atau gabungan. |
| Cara distribusi | Diakses melalui URL menggunakan browser; pembaruan aplikasi web umumnya dilakukan di server sehingga pengguna tidak perlu memasang ulang aplikasi. | Didistribusikan melalui installer, paket aplikasi, toko aplikasi desktop, atau pengelola paket. | Didistribusikan melalui toko aplikasi seperti Google Play dan Apple App Store, atau melalui mekanisme distribusi lain yang didukung platform. |
| Keunggulan | Mudah diakses lintas perangkat yang memiliki browser; pembaruan terpusat; pengguna biasanya tidak perlu menginstal aplikasi. | Dapat memanfaatkan sumber daya komputer dan integrasi sistem operasi; cocok untuk aplikasi produktivitas, pengolahan data, dan pekerjaan yang memerlukan fitur desktop. | Praktis dibawa; dapat memanfaatkan kamera, GPS, sensor, notifikasi, dan fitur perangkat lainnya; cocok untuk penggunaan saat bepergian. |
| Keterbatasan | Ketergantungan pada browser dan jaringan untuk sebagian fungsi; akses ke fitur perangkat dibatasi oleh browser dan izin keamanan. | Instalasi dan pembaruan dapat berbeda antar sistem operasi; kompatibilitas dan distribusi perlu diperhatikan. | Ukuran layar dan sumber daya lebih terbatas daripada komputer pada umumnya; perlu memperhatikan konsumsi baterai, variasi perangkat, dan aturan toko aplikasi. |
| Contoh aplikasi | Gmail versi web, Google Docs versi web, dan aplikasi web perbankan. | Visual Studio Code, LibreOffice, dan aplikasi desktop Blender. | WhatsApp untuk Android/iOS, Google Maps, dan aplikasi mobile perbankan. |

## 2. Refleksi

Platform yang paling menarik untuk saya pelajari adalah platform web. Menurut saya, platform web menarik karena aplikasi dapat diakses melalui browser dan digunakan dari berbagai perangkat tanpa harus memasang aplikasi khusus terlebih dahulu. Saya juga ingin memahami bagaimana HTML, CSS, dan JavaScript bekerja bersama untuk membangun antarmuka, serta bagaimana aplikasi web berkomunikasi dengan server. Pengetahuan ini dapat menjadi dasar untuk mengembangkan aplikasi yang bermanfaat.

Tantangan terbesar saat menyiapkan environment adalah memastikan setiap tools terpasang dengan benar dan dapat dikenali melalui terminal. Versi Git, Node.js, NPM, dan Java perlu diperiksa agar saya mengetahui bahwa instalasi berhasil. Selain itu, saya perlu memahami alur repository GitHub, mulai dari membuat repository, melakukan clone, menyimpan perubahan, hingga melakukan commit dan push.

Untuk mengatasi tantangan tersebut, saya akan memasang tools satu per satu mengikuti dokumentasi resminya, lalu menjalankan perintah versi yang diminta pada instruksi tugas. Jika muncul pesan error, saya akan membaca pesan tersebut, memeriksa PATH atau konfigurasi yang relevan, dan mencari solusi dari dokumentasi resmi. Saya juga akan membiasakan diri menggunakan Git melalui latihan kecil agar proses pengumpulan tugas berikutnya lebih teratur.
